# Feature inventory

Code review date: 9 October 2026. This inventory describes implemented behavior, not design exports or proposed features. Source paths are relative to the repository root. React routes are in `Frontend/src/App.jsx`; Laravel routes are in `backend/routes/api.php`, `backend/routes/web.php`, and `backend/routes/auth.php`.

## Architecture and roles

| Area | Confirmed implementation | Source |
|---|---|---|
| Client | React/Vite, React Router, TanStack Query; public data cached for five minutes; admin requests use session cookies and CSRF token. | `Frontend/src/App.jsx`, `Frontend/src/lib/publicData.js`, `Frontend/src/lib/admin.js`, `Frontend/src/lib/auth.js` |
| Server | Laravel web-session authentication, JSON public API under `/api/v1`, authenticated admin routes under `/admin`; conventional Blade auth/profile routes also exist. | `backend/routes/*.php`, `backend/bootstrap/app.php` |
| Guest | Read published/active public content; submit contact, group join and parish registration; sign up/login/reset password. | `backend/routes/api.php`, `backend/routes/web.php` |
| Signed-in unassigned user | Normally created by public signup after an account already exists; can access authenticated overview/profile and scoped empty admin collections. This is a distinct state from a group admin. | `backend/app/Http/Controllers/Auth/ApiAuthController.php`, `backend/app/Http/Controllers/Admin/OverviewController.php`, `Frontend/src/admin/useAdminSession.js` |
| Group admin | Signed-in user with `group_id` and `is_main_admin=false`; own-group events, messages, members and group read access; event publication forced to draft. | `backend/app/Models/Event.php`, `backend/app/Http/Controllers/Admin/{EventController,GroupMemberController,ContactMessageController}.php` |
| Main admin | `is_main_admin=true`; main-admin middleware protects mass times, newsletters, news, registrations, council, gallery, groups mutations and admin accounts. | `backend/app/Http/Middleware/EnsureMainAdmin.php`, `backend/routes/web.php` |
| First-account bootstrap | On an empty users table, the first `User::create` is automatically promoted to main admin, including via public signup. Email verification routes exist, but `User` does not implement the verification contract used by Laravel's `verified` middleware. | `backend/app/Models/User.php`, `backend/app/Http/Controllers/Auth/{ApiAuthController,RegisteredUserController}.php`, `backend/routes/auth.php` |

No separate subscriber table, newsletter subscription endpoint, public account profile route, payment processor, donation checkout, reports/export endpoint, role editor, or site settings editor was found. The registration `interests.weekly_newsletter` flag is a preference, not an email subscription workflow. Group join is a contact message, not automatic membership creation.

## Data model and dependencies

Migrations in `backend/database/migrations/` define `users`, `groups`, `group_members`, `events`, `mass_times`, `contact_messages`, `parish_registrations`, `parish_children`, `parish_interests`, `newsletters`, `news_posts`, `parish_council_members`, `gallery_images`, `audit_logs`, sessions, cache and jobs. Key dependencies: `users.group_id -> groups`; `events.group_id -> groups`; `contact_messages.group_id -> groups`; `group_members.group_id -> groups`; registration has children and one interest record. Uploaded event/news/council/gallery images and newsletter PDFs are served by dedicated routes; newsletters also support stored PDF bytes. Clash rules are in `backend/app/Rules/` and `backend/app/Services/ClashDetectionService.php`. Audit writes are in `backend/app/Support/Audit.php`.

## Security controls added during defect remediation

- Public registration always creates an ordinary account. Initial main-admin creation is an explicit local CLI operation: `php artisan admin:provision email@example.test`.
- Backend `/admin` routes and `/dashboard` require an authenticated main or group-assigned administrator. The React dashboard applies the same role decision.
- Public news images use the same status and publication-date gate as public news detail.
- Public contact submission accepts only defined categories and active group routing, persists the attendance answer, and is limited to five requests per minute per IP.
- Overview preference keys are resolved inside the caller's role scope before persistence.
- Newsletter PDF replacement stages the new file and commits database changes before removing the old file.
