QA-F01, QA-F02, QA-F06, QA-F08, QA-F09, QA-F10, QA-F11, QA-F13 and QA-F14 were confirmed as D-001 through D-009 and are now **Resolved and verified**. QA-F03, QA-F04, QA-F05, QA-F07 and QA-F15 still require a product decision or more execution. QA-F12 was not reproduced for retrieval completeness, while broader performance coverage remains open.

The expanded documented-case run also reproduced two new issues: D-010, a successful parish registration returning HTTP 200 instead of the documented 201; and D-011, a case-variant duplicate admin email reaching an unhandled unique-constraint HTTP 500 instead of validation HTTP 422. Both remain open because this execution was restricted from changing production application code.

## Requirements and product scope to confirm

- Public `/donate` and `/fundraising` provide information and contact links; payment processing is absent. Do not run payment tests against this project.
- No independent user profile page is exposed on the public React site; profile editing is restricted to administrators through `/dashboard/profile` and Laravel `/profile`.
- No roles editor, site settings form, reporting or export endpoint was found. The two effective admin roles derive from `is_main_admin` and `group_id`, not configurable permissions.
- Group join sends an enquiry and does not create a group member. Admins add a member explicitly from the message/group workflow.
- Newsletter public PDFs may be served from private filesystem or stored bytes. Live file permissions, CORS/cookies, SMTP delivery, reverse proxy upload limits and PostgreSQL behavior remain environment checks.

## Suggested execution order

1. **Critical security and data boundaries:** QA-F01/F02/F14, guest/group/unassigned direct routes, CSRF, private media, group IDOR, and registration atomicity.
2. **Core workflows:** public registration/contact/join; event scheduling; main admin CRUD; newsletter publication and downloads.
3. **Dependent data and faults:** group deletion/assignment, member duplicates, file replacement, failed mail/storage, audit trail.
4. **Browser quality and scale:** navigation, responsive layouts, filters/pagination, loading/error states and large lists.

Existing tests in `backend/tests/Feature/`, `backend/audit/AdminAuditTest.php`, and `Frontend/tests/adminPagination.test.js` were reviewed and extended. The execution reports distinguish tests that assert current behavior from cases that pass their expected result.
